# AGENTS.md

CLI pipeline for typhoon track maps (fetch → weathernext → ecmwf → plot_web). No test suite, no linter, no `requirements.txt`/venv. Verify by running the scripts.

## Setup

Python 3.8+ required. No venv or requirements.txt — install directly:
```
pip install requests matplotlib numpy cartopy
pip install shapely pyproj          # optional, for Taiwan 100km buffer
pip install ecmwf-opendata eccodes  # optional, for fetch_ecmwf.py
```

## Commands (order matters)

1. `python fetch_typhoon2000.py` — pulls multi-agency forecasts from typhoon2000.ph + CWA Open Data API, writes JSON to `output/`. Must run before plotting.
1b. `python fetch_weathernext.py` — reads the latest `output/各國颱風路徑.json`, walks each typhoon's CWA forecast-track points (tau 0/24/48...), and fetches Google WeatherNext 2 **ensemble mean** via the Open-Meteo **free** API (`https://ensemble-api.open-meteo.com/v1/ensemble`, `models=google_weathernext2_ensemble_mean`, `temporal_resolution=native` for 6h steps, `wind_speed_unit=kn`, `cell_selection=sea`, `forecast_days=6`). Writes `output/weathernext_各國颱風路徑.json`. No API key needed (Google's own GCP/BigQuery/Earth Engine channel requires a key — this project deliberately does NOT use it). Exit code 1 + printed message if no CWA track points / network failure. Known API facts: the main endpoint 400s on `wind_speed_10m_ensemble_spread/mean` + `pressure_msl_ensemble_mean` variables (use the single-variable `wind_speed_10m` etc. — verified working), and the `ensemble-mean` endpoint path 404s.
1c. `python fetch_ecmwf.py` — downloads the latest **released** ECMWF Open Data TC-track BUFR products (HRES `stream=oper` + ENS `stream=enfo`, both `type=tf`) via `ecmwf.opendata.Client(source='ecmwf')`, decodes with **eccodes**, matches storms to current typhoons by name, writes `output/ecmwf_各國颱風路徑.json` (`{run, typhoons:[{storm_name, hres[], ens_mean[], ens_control[], ens_members}]}`; per-point `{tau, lat, lon, pmsl_hpa, wind_ms}`). Free/no key, CC-BY-4.0 (attribute ECMWF). **BUFR decoding traps:** (a) `pdbufr` 0.14 returns **0 rows** for this file (issue #76) — use eccodes; `pybufr` 0.4 is Py2-era and TabErrors under Py3.13. (b) Do **not** `codes_get_array('latitude')` — it mixes 觀測中心/分析中心/最大風速位置 arrays; use ranked keys: `#n#timePeriod` = step n (hours), centre lat/lon at `#2n#`, max-wind pos at `#(2n+1)#`, centre pressure `#n#pressureReducedToMeanSeaLevel` (hPa), max wind `#n#windSpeedAt10M` (m/s); rank 1 = synthetic observation centre, so T+0 analysis centre is `#2#`. (c) ENS file = one BUFR message per storm with 51 subsets (members; member 51 = ENS control); HRES oper file decodes as a single track. (d) ECMWF uses a `MISSING` sentinel (-1e+100) for real values — filter it when averaging the ensemble. (e) One storm per message but a "duplicate" id (e.g. 71W duplicating 20W) can appear — match by `longStormName` instead. Run availability: 00/12z → step 360, 06/18z → step 144, released ~6-7h after run time (00z 06:55, 06z 12:12, 12z 18:55, 18z next-day 00:12 UTC); the script tries newest-first and falls back to an earlier run on 404. Exit code 1 if no download/no matching storm.
2. `python plot_typhoon.py [entry_index]` — renders `output/各國颱風路徑.png`. Optional arg = historical entry `index` from `output/各國颱風路徑_all.json`.
3. `python plot_web.py [--data-dir DIR] [--out NAME]` — renders `output/各國颱風路徑.html`, a **self-contained** Leaflet page (data embedded inline, open by double-click, no server). Re-run after `fetch` + `fetch_weathernext` + `fetch_ecmwf` to refresh. Uses Leaflet from CDN + Google map / Esri satellite tiles (optional Stamen terrain via `stadia_api_key` in `config.json`) → needs internet at page-open time. The Stamen terrain layer is only added when `stadia_api_key` is set (legacy tile.stamen.com is dead; Stadia requires the key). WeatherNext: **temporarily disabled in `plot_web.py`**. `fetch_weathernext.py` still exists and writes `output/weathernext_各國颱風路徑.json`, but the page no longer renders it — its points are sampled along the CWA/agency track, so the line merely duplicates CWA and is *not* Google's own predicted track (the free Open-Meteo endpoint only returns weather at a point, not a cyclone path). Re-enable only after switching to a data source that provides the actual Google WeatherNext 2 track. (Historical note: it used to embed the data when present as a per-typhoon overlay + tooltip/popup; the **teaching page** had none since `teaching/白海豚/` has no `weathernext_*.json`.) Embeds ECMWF data from `output/ecmwf_各國颱風路徑.json` when present (per-typhoon overlay `{name} ECMWF`: deep-indigo HRES solid `ECMWF_COLOR #4527A0` + light-indigo ENS-mean dashed `ECMWF_ENS_COLOR #7986CB`, colors const in the JS next to `drawECMWF`; degrades gracefully if absent — teaching page also has no `ecmwf_*.json`). Legend shows the ECMWF run string (`DATA.ecmwf_run`); help modal has an ECMWF section. Optional args support the **teaching page**: `--data-dir teaching/白海豚 --out 白海豚教材.html` reads frozen JSON from `teaching/` (not `output/`) and emits `output/白海豚教材.html`. The template auto-fills a cross link (`__NAV_LINK__`): live page → `📚 教材範例：白海豚`, teaching page → `↩ 回到即時更新網頁`; `__PAGE_TITLE__` differs too. Teaching page data is a **frozen snapshot** in `teaching/白海豚/` (`.json` + `_all.json`), regenerable anytime via the same command; `fetch` never touches `teaching/`.
4. `update_typhoon_web.bat` — one-click refresh for latest info: runs `fetch` → `fetch_weathernext` → `fetch_ecmwf` → `plot_web` (4 steps, `[1/4]`/`[2/4]`/`[3/4]`/`[4/4]` headers). The ECMWF step (`[3/4]`) is **non-fatal**: if `fetch_ecmwf.py` exits 1 (no matching storm / no download), the bat prints a warning and continues to plot_web (page degrades gracefully without the ECMWF layer). Double-click to run (pauses at end); add `nopause` arg for Task Scheduler (`update_typhoon_web.bat nopause`). File must stay **CP950 (Big5) + CRLF** encoded — re-encoding (e.g. UTF-8/LF) breaks cmd parsing; it fails with nonsense "not recognized" errors. **To edit it programmatically, read/write with `io.open(..., newline='')`** (default text mode applies universal-newline translation `\r\n`→`\n`, which silently breaks `split('\r\n')`/CRLF round-trips — verified bug last time). Note: `ecmwf.opendata` prints an access-conditions notice + a tqdm progress bar on stderr — harmless, ignore.
5. Deployment — this repo **is** the live site (GitHub Pages on `wslee513/MSTyphoontrackshop`, branch `main`; tracked `output/` files ARE the deployed artifacts; `output/index.html` is a meta-refresh redirect → `各國颱風路徑.html`). Two bats do git add/commit/push:
   - `deploy.bat` — manual deploy (`main`, falls back to `master` on push failure).
   - `scheduled_update.bat` — Task Scheduler variant, 5 steps: fetch → weathernext → ecmwf (non-fatal, like step [3/4] above) → plot_web → **git add -A / commit "Auto update YYYY-MM-DD HH:MM" / push origin main** (any failing step except ECMWF aborts before the commit).
   - ⚠️ It **runs hourly** (git log is full of hourly `Auto update ...` commits): the remote moves under you while you work, and `git add -A` sweeps **any** uncommitted change — including your half-finished source edits — into the next auto-commit and pushes it publicly. Check `git status`/`git log --oneline -3` when you start, commit or stash real work promptly, and expect your working tree to become dirty from fresh `output/` data at any time.

## Gotchas

- **Output filenames are hardcoded Chinese strings** in the scripts (`各國颱風路徑.json`, `各國颱風路徑_all.json`, `各國颱風路徑.png`, plus `weathernext_各國颱風路徑.json` / `ecmwf_各國颱風路徑.json` for the model layers). Do not rename/move them casually; the scripts depend on exact names.
- `fetch` and `plot_typhoon` **require network + a valid `cwa_api_key`** in `config.json` for the CWA API (fetch: typhoon-name auto-detection; plot: radius lookup — degrades to estimates on failure). **`config.json` is gitignored (local-only)** — a fresh clone has no key; create it from the shape documented in `README.txt`. Fallback for fetch: add `"typhoon_name"` to `config.json`; `fetch` exits with code 1 if neither works.
- `plot_typhoon.py` **blocks on a tkinter selection dialog** when 2+ typhoons are present (auto-confirms after 5.16 s). Headless: falls back to stdin input. `fetch` has **no** such dialog — it processes every active typhoon (README.txt's old claim about a fetch selection window is stale).
- `plot_typhoon.py` sets Chinese font `Microsoft JhengHei` via `plt.rcParams`; other fonts are fallbacks. Keep Chinese font first.
- `show_taiwan_100km_buffer: true` needs `shapely` + `pyproj` (optional deps) and cartopy Natural Earth data (downloaded on first run). If `HAS_GEOM` is False it prints a skip message rather than failing.
- JSON data format: `{"typhoons": [...]}`. `fetch` injects `_`-prefixed metadata (`_fetch_name`, `_storm_name_cn`, `_max_wind_ms`, `_cwa_fc_mws_map`, `_cwa_fc_mws_map_by_tau`) that the plotter consumes; if you add fetch fields, keep the `_` convention and forward them the same way (add to `LATEST_EXTRA_FIELDS` in `plot_web.py` too).
- Historical entries in `_all.json` have **no `_` metadata** (only the latest one does); `plot_web.py` copies typhoon-level `_` fields onto each entry so grades render for past selections.
- `plot_web.py` **never calls the CWA API** (generation is offline; page is static). Static forecast view draws **no** storm circles anymore (they used to cover the CWA track and block mouse selection) — wind radii are instead shown in the CWA point popup. Radius logic now only feeds the **playback quadrant polygons** and the **pin** feature. **4-quadrant radii** are drawn as **dashed** polygons (red `CWA_COLOR` / orange `#FF8C00`, `dashArray: '8 4'`), while **average radii** are drawn as **solid** circles. Both use white halo underlay via `polyWithHalo(dashed=true/false)`. Radius sources prefer the `_cwa_fc_radius7_map[_by_tau]` / `_cwa_fc_radius10_map[_by_tau]` maps that `fetch_typhoon2000.py` stores (CWA `Circle15ms`/`Circle25ms`, forwarded via `LATEST_EXTRA_FIELDS`), else fall back to wind-speed estimates (`windKtToRadius` / `windKtToRadius10`, same numbers as `plot_typhoon.py`'s `estimate_radius_from_wind`). CWA `W-C0034-005` returns `Circle25ms` only for storms strong enough to reach ten-level wind (十級風, ~25.7 m/s); weak storms omit the field, so their ten-level (orange) circles fall back to `windKtToRadius10`, which is 0 below 50 KT. Note: the PNG plotter (`plot_typhoon.py`) does **not** estimate ten-level radius at all — it skips the circle when CWA data is missing, so PNG and web disagree for weak storms.
- **CWA 4-quadrant radii** (`QuadrantRadii` NE/SE/SW/NW) exist **only in `AnalysisData.Fix`** (nowcast/history); `ForecastData.Fix` has a single `Radius`. `fetch` stores them position-keyed (`f"{lat:.1f},{lon:.1f}"`, CWA `CoordinateLatitude/Longitude` rounded to 0.1) as `_cwa_an_radius7_quad_map` / `_cwa_an_radius10_quad_map` (plus `_cwa_an_radius7_map`/`_cwa_an_radius10_map` single-radius, and `_cwa_an_*_quad_latest`), all forwarded via `LATEST_EXTRA_FIELDS`. The web page's **playback marker** draws these as 4-quadrant polygons (`quadrantCirclePoints`) that morph/move along the grey track via `buildQuadTimeline` + `quadAt` (linear interpolation between entry fixes); positions without quadrant data fall back to circular `windKtToRadius` estimates (`circleRadii` makes equal-radius polygons). Quadrant circles appear ONLY during playback (they are not drawn in the static view). Key gotcha: the JS key must use `.toFixed(1)` on both coords (a raw `21` vs `21.0` mismatch silently drops hits for integer coordinates). Other agencies (JTWC/JMA/NMC/HKO/KMA/PAGASA) carry **no** radius data at all. Quadrant polygons are NOT drawn in the static view — only during playback and in pins.
- **4-quadrant radii are DASHED lines** (`dashArray: '8 4'`) while **average radii are SOLID lines** in `plot_web.py`. The only dashed element is the grey historical track. The quadrant radii use the same colors (red `CWA_COLOR` for 七級, orange `#FF8C00` for 十級) with white halo underlay. If you add new radius-circle code, follow this pattern (quadrant = dashed, average = solid).
- **Pinned wind circles** (`pin-btn`/`clear-pins-btn`/`pin-list`, JS `pins` array + `pinCurrentTime()`/`drawPins()`, layer `pinsGrp` registered as overlay `固定風圈標註`): clicking 「固定此時間風圈」 captures each typhoon's 7/10-level wind circle at the current `playback.clock` (same quadrant-vs-estimate logic as the playback marker), draws them as solid polygons, and lists the LTC time in the panel (individual ✕ or clear-all). Pins are NOT cleared by `stopPlayback('reset')`/`clearMarkers` — they persist until removed. Dedup is by typhoon index + rounded time.
- `plot_web.py` embeds the Taiwan 100km maritime line by **importing `plot_typhoon.get_taiwan_100km_buffer()` at generation time** (so `plot_web.py` pulls in cartopy/matplotlib/shapely on import — fine, they're required deps). It needs `show_taiwan_100km_buffer: true` + shapely/pyproj + cached Natural Earth data; otherwise it embeds `null` and skips the overlay gracefully.
- The web page's time playback builds a per-typhoon timeline (historical tau=0 points + selected entry's forecast points), interpolates a moving marker, and reveals agency polylines by absolute time; if you change the embedded data schema, keep `forecast_time_utc` and `tau` semantics intact or playback breaks.
- CWA **storm radius is stepped, not interpolated**: `quadAt` holds the previous CWA radius value and jumps only at a CWA-specified time (`T < b.t` boundary), so the circle changes exactly at the forecast issue time, never smoothly between. Do not re-add `mixAvg`/lerp.
- **Graticule overlay** (`經緯度線`): 5°-spaced lat/lon dashed lines via `buildGraticule`, registered as a layer-control overlay **defaulting on**; toggle it in the layer panel. Display-only (`interactive:false`).
- **`forecast_time_utc` robustness**: TD / CWA-only entries sometimes lack a CWA `InitialTime`, leaving `forecast_time_utc` empty. `fetch_typhoon2000.py` now borrows the shared CWA bulletin base from a sibling typhoon that has one. In the page, `utcToLTC`/`fcTimeLTC` return `—` (not `?`) for empty/malformed times, and the header `預報時間` (`firstValidFtu`) uses the first typhoon with a valid time instead of always `typhoons[0]`.
- **Typhoon-center marker is intensity-coded (颱風標誌)**: the playback moving marker AND the static `tau===0` forecast point use `typhoonCenterIcon(windMs, color)` (SVG `L.divIcon`). It draws the CWA typhoon glyph — an eye-wall circle + center eye dot + **two curved spiral arms (top & bottom)** for all typhoon grades (`td` <17 m/s: plain grey circle, 0 arms). Color encodes intensity (not per-storm): `light` (17–32) = **hollow** dark circle, `medium` (32–51) = **green solid** circle (`#22B573`), `strong` (≥51) = **bright-red solid** circle (`#FF2D2D`); eye/arms white on the filled ones. The moving marker refreshes its icon via `setIcon` when the tier changes during playback. Thresholds are the user-specified 17/32/51 m/s (not the CWA grade config).
- The web page has a per-agency visibility toggle (`hiddenAgencies` Set): `drawForecast` skips hidden agencies, and toggling redraws every typhoon forecast group (or re-runs `renderPlayback` while playing). Historical merged grey tracks are NOT affected by the toggle.
- Playback has ±1h step buttons (`prev-hour-btn` / `next-hour-btn`) implemented via `nudgeClock(dh)`; it pauses playback and clamps to `[tStart, tEnd]`. The clock **snaps to whole hours** on the 「📍 現在時間」 button (`floorHour`), on slider drag, and on the ±1h nudge (`snapHour`), so the readout shows `HH:00` (the `now` button floors the real current time instead of keeping minutes). Playback animation still sweeps continuously (minutes appear while playing).
- Winds are in **knots (KT)** in JSON (and internally for radius estimates); the web page **displays m/s** via `ktToMsStr` (`kt * 0.514444`). CWA grade thresholds in `config.json` are **m/s** (`wind_kt * 0.514444`).
- **Radius labels**: playback quadrant polygons and pinned circles each carry a small contour-style label tooltip at the circle's top (north) point showing the radius in km (e.g. `180 km`, red `r7` / orange `r10` classes, `.radius-label` CSS). `northRadius()` = `max(NE,NW)`, positioned via `lat + rKm/111.32`. Labels live in `radiusLabelGrp` (playback) / `pinLabelGrp` (pins), both `L.layerGroup`; playback labels are updated per frame with `updateRadiusLabel` and removed in `clearMarkers`. Note these layer-group consts are initialized **after** `const map` (they reference `map`), while the helper functions are plain declarations.
- `fetch_typhoon2000.py` parses JS variables (`text[N] = "..."`) out of the typhoon2000.ph HTML, falling back to `data/{bare_name}.TXT` where `bare_name` strips the `_YYYY` year suffix. Parser changes must be validated against both source shapes.
- `fetch_typhoon2000.py` handles TDs (Tropical Depressions) without typhoon names from CWA API: generates synthetic names like `TD22_2026`, builds CWA-only forecast entries when typhoon2000.ph has no data, and stores `StateTransfer` info in `_td_state_map` (tau → zh-hant text, e.g. "轉變為熱帶性低氣壓"). The web page shows state transfer in CWA forecast point popups.
- Requests to the CWA API use `verify=False` and suppressed urllib3 warnings — expected, don't "fix".
- `色碼參考.txt` documents the agency color choices now in `config.json` (`agency_colors` overrides the hardcoded `AGENCY_STYLE` defaults in `plot_typhoon.py`).
- `plot_web_check.exp.js` (repo root) is a **hand-maintained Node snapshot** of the page's inline JS + one embedded DATA payload (`module.exports`; runnable with `node` for headless logic checks). No script regenerates it — editing the JS inside `plot_web.py`'s `HTML_TEMPLATE` silently desyncs it. The repo-root `颱風消息與警報-熱帶氣旋路徑.json` is a saved raw CWA `W-C0034-005` response, also unused by the pipeline.
- `output_backup_20260814_nangka/` is a frozen backup of output from a previous typhoon (Nangka) — not referenced by any script.
